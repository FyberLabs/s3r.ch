# Optional shared browser payload admission (#570)

`createSharedTransferBudget({maxBytesPerMinute, current})` provides an IndexedDB rolling-minute ledger shared by participating clients on the same browser origin/storage partition. Pass it as `sharedBudget` to `createKuboBlockClient`. The Kubo client reserves before hashing/upload or download dispatch; failure refuses the network request. No default activation, native UI, reader registration or account identity is added.

All participating tabs share one aggregate ledger, regardless of account or provider. A caller-selected limit is 1 byte to 8 MiB per rolling minute; each admission must fit that caller's limit against the existing aggregate. There are at most128 retained admissions per minute and each payload is at most1 MiB. Read/write transactions serialize competing reservations. Records contain only timestamps and payload sizes, never identifiers, URLs, CIDs, keys or ciphertext. Expired entries are pruned on admission. Closing/recreating instances or reloading a tab does not reset committed reservations.

Admission charges requested payload even if the provider fails, the browser cancels, or current authority is withdrawn after commit. There is no refund or automatic retry. Existing per-client lifetime/rate/attempt/concurrency limits remain active. This shared ledger limits payload admission, not wire bandwidth, internal browser retransmissions, cross-tab in-flight requests, or cache-local reads. Different configured limits do not establish a centrally administered policy: a higher-limit caller can admit beyond a lower caller's threshold, while the hard8MiB cap always applies to participating clients.

Storage open/transaction stages have two-second deadlines; two pending reservations are permitted per instance. Blocked/denied/corrupt storage fails closed when the option is installed. Invalid timestamps and wall-clock rollback behind a persisted watermark refuse admission. Forward clock jumps, clearing site data, separate profiles/origins, scripts bypassing the option, or constructing unbounded instances are outside this cooperative browser boundary. This is not a tamper-resistant account quota or trusted time service. Native integration must supply current authority and install the same policy across its transports; the existing unconfigured path retains its per-instance limits.

`close()` stops this instance and aborts outstanding transactions but does not erase shared state. The Kubo operation's abort signal and ten-second deadline include admission. A committed reservation remains charged after late cancellation; no provider call is made when admission or the subsequent current check fails.

Six focused tests use substituted IndexedDB with real Kubo-client admission paths: competing instances, reopening/expiry, failed-provider charging, late revocation, pre-open refusal, rollback/attempt cap and unavailable storage. PR CI uses actual Chromium tabs at one origin, racing one payload allowance and asserting exactly one provider request, persistence across reload, next-window admission and rollback refusal. The clock and Kubo provider are explicit substitutes. Live-provider, native mounting and account-level qualification remain open; readers stay unregistered.
