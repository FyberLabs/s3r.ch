# Optional shared browser operation slots (#570)

Pass `createSharedTransferConcurrency({current})` as `sharedConcurrency` to `createKuboBlockClient` to bound participating same-origin/storage-partition clients to two active operations. Two fixed exclusive Web Locks cover shared payload admission, hashing, provider fetch, bounded response reading and CID verification. A third operation is refused without network dispatch or a waiting queue. Each instance also bounds outstanding slot attempts to two. Missing/denied Web Locks fail closed when this option is installed; there is no in-memory fallback.

The slot is held until the underlying operation settles. Cancellation and the existing ten-second Kubo deadline reject the caller, but an abort-ignoring injected transport continues to occupy its slot until it settles. Browser tab destruction releases browser-owned locks. No wall-clock lease, durable state, credential, CID or provider address is stored in the lock names. Current authority and cancellation are checked before requesting, after acquisition and before returning success. Callers must still supply authenticated current grant/consent and the operation abort signal.

Slots are independent of the optional rolling payload ledger: use both to bound participating operations and admitted bytes. A refused slot still consumes existing per-client lifetime/rate/attempt reservations but does not reach the shared payload ledger. Failed operations release their slot without refunding any payload already reserved. There are no automatic retries, waiting jobs or new provider connections after cancellation.

This is cooperative browser coordination, not account-wide enforcement, a provider connection limit or a distributed service quota. Other origins/profiles, bypassing the option and browser-internal networking are outside it. Native activation remains unmounted and readers remain unregistered. No provider provisioning or automatic cloud fallback is added.

Unit tests substitute a lock manager and exercise competing clients, saturation, abort-ignoring work, failure/revocation cleanup, delayed acquisition and Kubo dispatch. PR CI uses actual Chromium Web Locks across two tabs with a deliberately stalled HTTPS Kubo substitute: a third operation sends no request, tab closure frees one slot, another read succeeds, and explicit abort releases the remaining slot. Live-provider and native qualification remain outstanding.
